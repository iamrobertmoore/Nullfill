Your transfer did not fail.
It never happened.

Robinhood Chain screens transactions at the sequencer. A screened transfer is never sequenced, so it produces no revert, no receipt, no event and no gas. Every contract, indexer and counterparty on the chain sees nothing at all.

Since a blocked transfer is never processed, it simply appears as though the event never occurred. Robinhood Chain developer documentation

What this tool will not claim

  • A failure receipt cannot tell you why. A contract revert and a transaction that arrived by force inclusion and was forcibly failed both produce a receipt with a failure status, no logs and burned gas. The receipt alone cannot separate them.
  • Screening is only ever directly observable at submit time. If you did not send the transaction, you can never be certain it was screened rather than dropped. From outside, both leave nothing.
  • The restricted address list is private. Addresses are stored as salted hashes so the list cannot be enumerated. Nothing here tries to reverse it, and nothing here can tell you whether a given address is on it.
  • Screening happens before execution, so the EVM cannot catch it. A transfer to a restricted recovery address does not revert, it simply never runs. No contract can detect that from the inside, which is why the recovery address has to be nominated in advance.
